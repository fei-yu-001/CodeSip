# CodeSip：Obsidian 笔记阅读与同步方案

状态：首版代码、后台、阅读器及插件已实现。实际已验证能力与剩余限制以仓库 README 和验收记录为准。

## 产品目标与已确定的选择

CodeSip 同时提供代码项目阅读、审阅和学习笔记阅读。用户在电脑上继续使用 Obsidian 和 AI 整理笔记，手机只负责查阅。

用户已选择把笔记同步纳入 CodeSip 后台，现有服务器作为部署目标。不依赖 Obsidian 付费 Sync，也不需要接入 Obsidian 官方账号体系。

手机登录 CodeSip 账号，电脑插件使用该账号为单个笔记库生成的专用连接。代码项目、笔记库及其附件统一由后台管理，共同建设账号、文件存储、版本清单、搜索和同步基础；源码与笔记分别使用适合的阅读视图。

首版提供手机 Web/PWA 阅读器与鸿蒙 ArkWeb 工程；浏览器流程已验证，鸿蒙真机流程待验收。

## 建议的数据流程

电脑 Obsidian 笔记库 → 桌面同步插件 → CodeSip 后台 → CodeSip 手机阅读器。

- 电脑是笔记内容来源。用户选择需要同步的目录，并包含这些笔记引用的附件。
- 插件在 Obsidian 运行时监听创建、修改、重命名和删除事件；启动时核对文件清单，补传未运行期间的变化。
- 合并短时间内的连续修改，避免 AI 分段写入时频繁上传中间内容。
- 后台按账号及笔记库保存文件清单、版本信息、笔记和附件；同步失败后重试，界面显示最后成功同步时间。
- 手机打开应用或手动刷新时拉取更新，缓存后离线阅读。首版对电脑笔记正文仅提供读取能力。
- 电脑关机后，手机仍可读取已上传或已缓存的内容。纯插件方案需在 Obsidian 运行时上传新变化；以后若需要退出 Obsidian 后仍同步，可增加独立桌面同步程序。
- 手机上次阅读文件单独保存在本机，不回写电脑笔记正文；精确阅读位置与收藏尚待实现。

## 后台如何共用

一个 CodeSip 后台提供统一入口，并在内部区分代码项目和笔记库。

| 共用能力 | 在代码项目中的用途 | 在学习笔记中的用途 |
| --- | --- | --- |
| 账号和会话 | 访问自己的项目 | 插件上传、手机读取自己的笔记 |
| 文件存储和目录清单 | 保存导入的源码与项目目录 | 保存 Markdown、图片与附件 |
| 版本与变更清单 | 获取项目更新 | 获取增量笔记更新和删除记录 |
| 搜索 | 文件名与源码内容查找 | 标题与笔记正文查找 |
| 手机缓存 | 离线读代码、恢复阅读位置 | 离线读笔记、恢复阅读位置 |

代码项目仍沿用源码导入的产品方向。Obsidian 插件仅负责笔记及相关附件；代码分析与笔记渲染分别实现。

后台已按工作区服务器入口独立部署，监听 127.0.0.1:4318，使用自己的数据库与系统服务。部署边界见 deployment.md，实际验收结果见 verification.md。

## 首版范围

1. 桌面插件：账号下的笔记库专用连接、选择同步目录、手动同步、变更后自动同步、状态与错误提示。
2. 同步服务：登录和会话、账号下的笔记库、文件清单与版本、上传和读取接口、附件存储。
3. 手机阅读：笔记目录、全文搜索、Markdown 正文、代码高亮、图片、基础 Wikilink 跳转、离线缓存、上次阅读文件记忆。
4. CodeSip 首页：「代码项目」与「学习笔记」两个入口，共用目录和搜索等交互基础。

## 需要重点验证的部分

- Obsidian 的 Wikilink、同名文件、相对路径、附件引用和文件重命名后的跳转。
- 图片与正文更新的先后关系，确保同步完成后不会出现缺失附件。
- 同步中断后的重试、重命名和删除的传播、中文与空格路径，以及旧版本不会覆盖较新内容。
- 真实笔记是否大量使用公式、Mermaid、Canvas 或其他插件生成的内容。普通 Markdown 阅读不代表完整兼容这些功能；按真实笔记分阶段适配，必要时由电脑导出静态内容。
- 鸿蒙真机上的长文、长代码块、图片加载与离线存储表现。

## 工作量与验收

笔记阅读功能包含桌面插件、同步服务和手机阅读器。与代码阅读一起建设账号和文件管理基础，可减少重复工作；只读手机端也减少了双端正文编辑冲突。可靠同步与内容兼容仍需要实际开发和验证。

代码阅读保持产品开发主线，先建设共用账号和文件管理基础。笔记功能的首个里程碑是用包含图片、代码块和基础双链的少量样例验证完整链路，随后再扩大规模。

首个验收场景：电脑修改一篇带图片和代码块的笔记，插件报告同步成功，手机刷新后正确显示；手机断网后仍可阅读，笔记链接可以打开已缓存的目标。
