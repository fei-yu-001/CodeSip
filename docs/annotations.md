# 阅读批注

批注独立保存在 CodeSip 数据库的 `reader_annotations` 表。代码和笔记原文保持只读，添加、修改或删除批注不会改变库的同步版本，也不会经 Obsidian 插件写回原文件。

## 保存、离线与冲突

保存先写入本机，收到服务器确认后显示「已同步」。网络失败时显示待同步状态并保留草稿；重新打开文件、联网、刷新或点击重试都会尝试继续同步。离线删除保留待删除记录，确认服务器删除成功后才清除。

其他设备修改或删除了同一条批注时，当前草稿保留并显示「冲突」。用户可以选择保留本机版本或采用服务器版本；若服务器记录已删除，保留本机版本会创建新的独立批注。编辑器打开期间发生的远端修改也参与版本检查，不会因后台刷新而被未提交的编辑覆盖。

会话自动过期保留按账号隔离的本机批注，重新登录同一账号后继续处理。主动退出会清除本机离线副本和未同步草稿，退出弹窗会明确提示；服务器已同步的内容保留。

## 会话与隔离

接口仅接受网页登录会话，沿用写请求来源校验。插件凭据和 Bearer 凭据不能读取或修改批注。每次操作都校验库所属账号；同名文件位于不同库时，其批注相互独立。

## 接口

基础路径为 `/api/libraries/:id/annotations`，路径参数需 URL 编码。

| 操作 | 请求 | 成功响应 |
| --- | --- | --- |
| 列表 | `GET ?path=<文件路径>` | `{annotations: ReaderAnnotation[]}` |
| 保存 | `PUT /:annotationId`，正文为 `AnnotationWrite` | `{annotation: ReaderAnnotation}` |
| 删除 | `DELETE /:annotationId`，正文为 `{expectedUpdatedAt: number}` | `{ok: true}` |

类型定义位于 `shared/types.ts`。`ReaderAnnotation` 包含 `id`、`path`、`line`、`snippet`、`note`、`createdAt` 和 `updatedAt`。两个时间戳均由服务器生成，单位为毫秒。

`AnnotationWrite` 包含 `path`、`line`、`snippet`、`note` 和 `expectedUpdatedAt`。新建时版本为 `null`；编辑或删除时使用上次读取的 `updatedAt`。客户端在失败重试时保留同一批注 ID。

同内容保存重试返回已经提交的记录，不再改变版本。其他设备已修改或删除时，不同内容的旧版本请求返回 HTTP 409，客户端应保留本机草稿，供用户检查和处理。收到成功响应后才能标记为已同步。

## 数据边界

- 批注 ID 长度为 1–100，只允许字母、数字、下划线和连字符。
- 行号为 1–2000000 的整数；引用最多 2000 字符，正文去除首尾空白后不能为空，输入正文最多 10000 字符。
- 新建批注要求目标文本文件存在。既有批注不能移到其他路径。
- 单文件最多 500 条有效批注；单账号累计最多 5000 条记录，包含删除标记。
- 删除只保留标识和版本等必要元数据，并清空批注正文与引用，防止离线设备重建已经删除的记录。删除整个库会级联删除其全部批注与删除标记。
- 原文件被同步删除或改名后，批注仍保留在原路径，可由接口读取以便恢复；不会自动猜测并迁移到新文件。
- 批注随独立 SQLite 数据库备份。此版本只新增表和索引，旧服务可忽略这些表以便回滚。

离线草稿与本机旧批注不代表已上传。跨设备读取以服务器成功保存的记录为准。手机更换设备或清理应用数据前，应先确认需要保留的批注已同步。
