# 阅读器架构优化 · 2026-11-25

## 完成的改动

Markdown 解析、GFM、Wiki 链接转换和语法高亮移入独立 Web Worker。整篇解析保留跨章节引用定义、代码围栏、表格和列表语义；根据 AST 工作量将结果分成顶层块。主线程在上一批完成绘制后再拉取下一批，不同时创建整篇 React 树。切换文档/编辑版会终止旧 Worker，解析错误显示重试，不执行文档中的 HTML/代码。

大纲直接从解析结果生成，包含尚未挂载的章节；跳转会等目标段落挂载。源行号仍用于搜索定位与批注。原有 React 组件继续处理表格、链接、图片、代码复制/全屏等操作，未引入 HTML 注入。加载完成后保留完整 DOM，页内查找和选段可用。阅读位置随分批内容增长恢复。

与现有 agy 协作修复：

- 稳定文件导航回调；相同云端副本状态不会触发无意义的本地写入和正文更新；保存失败仍会对相同草稿重试真实持久化。
- 已成功加载同一账号/库/路径/散列的文件在网络状态切换时保留正文与阅读位置；失效请求可取消，错误联网后仍可重试。
- 库内图片在距视口 480 像素以内才开始读取，最多 4 个请求；重复图片按账号/库/散列共享下载，校验 SHA-256 后使用。
- 图片缓存最多 48 项/16 MiB，单项超过 8 MiB 不入缓存。缓存清理有代次隔离，退出账号清空；每个组件单独管理 ObjectURL。未改变用户主动“保存离线”的语义。
- 修复取消运行中的图片任务后队列未继续的问题；补充回归验证。

浏览器依赖 `decode-named-character-reference` 默认浏览器导出需要 DOM；构建显式选择该包已有的不依赖 DOM 的实现，使 Worker 与离线应用都可用。依赖版本保持现有锁定版本，仅显式声明直接使用的包。

## Rust 判断

服务器同一份 641,620 字节正文的 SQLite 读取平均约 1.15 ms；旧版真机主要开销是主线程整篇解析/重复渲染和图片并发。此次先调整执行位置、任务粒度和请求调度，没有把后端重写为 Rust，也没有宣称已测得 Rust/Wasm 加速收益。

Worker 协议将字符串输入与可克隆的 AST 分块输出隔离；未来若需要替换解析实现，可先验证 Rust/Wasm 对 GFM、Wiki 链接、源行号、代码高亮和不执行原文的兼容性，并比较总耗时/内存。更换语言不能直接消除 DOM 挂载与图片网络成本。

## 发布后真机结果

在同一连接手机（HarmonyOS API 26 / ArkWeb 7.0）确认 Web 版本 `2c160c3e8230`，通过应用内校验下载和重载更新，未清理用户数据。读取同一 641,620 字节笔记，三次测量期间页面一直保持前台，最终均为 20,865 个正文 DOM 节点：

| 次数 | 首批正文出现 | 全部正文挂载 | 主线程总阻塞 | 最长长任务 | 期间文件读取请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 3.678 s | 8.010 s | 90 ms | 113 ms | 1 |
| 2 | 2.998 s | 7.129 s | 0 ms | 无超过 50 ms 的任务 | 1 |
| 3 | 2.915 s | 7.086 s | 0 ms | 无超过 50 ms 的任务 | 1 |

总阻塞按各个超过 50 ms 的主线程任务累计 `duration - 50 ms`，0 不代表没有计算工作。对照旧版两次成功记录的 6.63/6.10 s 总阻塞，连续冻结已显著减少；全部内容仍需要约 7–8 s 渐进挂载。首次正文时间也包含网络与 Worker 初始化/解析，不能直接归为解析速度。旧版有一次网络超时，未用它计算加速比例。

额外只读交互验证：首批正文出现、后续仍在挂载时，程序触发阅读设置到对话框出现约 95 ms。随后 3 秒脚本驱动滚动采样 181 帧，平均帧间隔 16.65 ms、P95 16.70 ms、超过 33.4 ms 的帧为 0；不等同于触控硬件输入延迟测量。所有测量未改原文、批注或编辑副本。

测量结束后返回笔记主页，恢复原签名 HAP 并移除临时 CDP 转发，保留新版网页缓存及应用数据。
