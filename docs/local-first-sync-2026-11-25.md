# 本地优先阅读与手动同步 · 2026-11-25

> 本文记录 18:17 首次发布。19:34 的真机修复、增量同步和复测结果见 [真机复测](phone-localfirst-2026-11-25.md)。当前普通同步更新本机已保存文件；完整项目下载使用“保存离线”。

## 原因与证据

用户在 Rust 后端上线后仍反馈手机不流畅，随后明确要求客户端平时本地存档、顶部刷新改为手动同步。

本轮确认真机已加载 Web `2c160c3e8230`，后台确为 Rust。手机一次目录请求约 4,281.5 ms，随后正文请求约 7,077.9 ms；两者串行等待，普通读取的正文原先没有自动存入 IndexedDB。启动又依次等待状态、登录会话、资料库接口，批注在打开、聚焦和重新联网时还会自动读取或上传。后端更换语言没有消除这些等待。以上是一次现场网络样本，不能视为稳定网络基准。

补充的系统触摸注入测试在正文加载完成后记录到合成线程滚动；采样 trace 的 1,162 个有更新帧中，1,161 个完整呈现、1 个部分呈现，无 `STATE_DROPPED`、无高延迟标记，主线程没有超过 50 ms 的任务。SmartPerf 活动区间多次记录 115–120 fps。此结果仅描述这次场景，不证明所有页面、真实手指操作都流畅，也不能用服务器性能代替手机体验。

## 新行为

- 有本机账号与存档时，启动和目录切换直接读取本机，不等待会话、资料库和文件目录请求。打开过的文件经 SHA-256 校验后自动持久保存，缓存仍按账号、资料库与文件散列隔离。
- 首次打开尚未保存的项目或文件需要联网；首次打开没有本机记录的批注/编辑版，会尝试读取一次。读取不阻挡原文阅读，已有记录以后不随聚焦、重新联网或页面打开自动拉取。
- 批注与编辑版先保存到本机，重开应用、离开文档、恢复网络不会自动上传。编辑器的“保存编辑版”保存到本机；显式冲突处理与“立即重试同步”仍可发起相应上传。
- 顶部入口显示“同步”，执行时显示进度并防止重复点击。文档内同步当前项目及有本机阅读记录的项目；首页同步已打开过的项目，同时刷新云端项目列表。尚未打开、无本机记录的项目不会自动下载全库。
- 同步校验账号后上传待同步批注/副本，包括不在当前阅读页的记录；随后读取批量元数据并下载全部变更文件。每库两个下载并发，已保存且散列相同的文件不重复下载。
- 只有所有文件写入成功才更新本机目录与完整离线标记。下载失败、断网或空间不足保留旧目录和已保存文件，下次同步可以复用已验证的下载。各库独立完成，并非跨库的单个原子事务。
- 云端已删除的项目保留本机存档；本机批注或编辑版有版本冲突时保留双方内容，由用户明确选择。未同步修改存在时提示待处理数量，不声称全部同步成功。
- 完整离线项目的全文搜索也在本机进行；只保存部分文件时，显式全文搜索仍可请求服务端。
- 本机存档可在会话过期后继续阅读；下一次联网同步或其他需要鉴权的请求检测到过期时要求重新登录，并保留未同步草稿。主动退出仍按现有提示清除本机私人数据。

## 实现边界

新增 `GET /api/libraries/:id/reader-state`，在一个 SQLite 读取事务中返回该库未删除批注和个人编辑版，避免同步时每篇两次 HTTP 请求。它只允许网页登录会话，拒绝插件令牌和其他账号，响应保持 `no-store` 并可压缩。不改数据库格式、原始导入内容、插件同步协议或游戏服务。

客户端文档存储从组件生命周期独立出来，上传期间继续编辑时保留新内容并推进其版本基线；退出时使在途响应失效。草稿写盘失败不显示保存成功，重试相同内容仍会再次尝试写盘。

应用外壳更新仍使用原有 Service Worker 下载与确认机制；“同步”负责笔记数据，应用更新入口继续在账号菜单。无需清除应用数据。
