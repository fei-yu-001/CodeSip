# 手机性能排查与后端修复 · 2026-11-25

## 真机证据与职责

本轮在已连接的 HarmonyOS API 26 / ArkWeb 7.0 手机上，对现有 Web 版本 `e7a077883eef` 做只读采样。前端由 agy 按用户安排优化，本轮代码改动限于后端、回归测试和部署兼容检查。

- 实测约 642 KB 的 Markdown，打开三次分别约 18.55、18.32、19.55 秒；文档约 20,865 个 DOM 节点，主线程阻塞时间约 6.93、6.28、7.97 秒。网络、旧页面未取消的图片请求和渲染互相影响，样本不能当成稳定性能基准。
- 加载完成后的滚动大多接近 60 帧；临时关闭背景滤镜未显示稳定且显著的优势，不把全部卡顿归因于玻璃效果。
- 服务器同一正文的 SQLite 读取 10 次平均约 1.15 毫秒。当前证据指向客户端整篇解析、重复挂载与图片并发请求，尚不支持为此将整个后端重写成 Rust。
- 抓取工具、原始计时、手机截图均在忽略目录 `.local/mobile-performance/`；不提交真实笔记路径、正文、用户数据或调试签名包。

## 后端变更

- v1 同步的笔记、设备和附件改用 `(user_id, 本地标识)` 联合主键。相同笔记 ID、设备 ID、附件散列可以分别归属不同账号，读取正文也显式限定账号。
- 旧表在同一 SQLite 事务中迁移，保留数据、设备密钥和已有同步序号；迁移失败整体回滚。启动重试不会重复迁移。
- 私有 v1 附件保留 `Cache-Control: no-store`，不进入共享缓存。
- 正文和文件清单按客户端 `Accept-Encoding` 按需 gzip；使用异步低压缩级别，短响应、图片和含登录/连接令牌的接口不压缩。仍校验鉴权、账号归属，并保持 `no-store`；解压后的字节及 SHA-256 不变。
- 真机样本文本快速压缩可从 641,620 字节降至约 185,649 字节，减少约 71%。这只减少传输量，不代替前端渲染优化。

## 验证与部署边界

新增回归覆盖跨账号同标识覆盖/删除、附件共同持有、插件权限、私有缓存、旧表迁移重启与失败回滚，以及正文/清单压缩、拒绝 gzip 的请求、散列一致性和鉴权。

同步表主键迁移后，旧程序的单列 `ON CONFLICT` 不兼容。部署脚本遇到验证失败时会先比较迁移前后同步主键；若已变化，保留当前程序与数据并报告错误，防止自动切回不兼容程序。应发布兼容修复，不直接覆盖线上新数据。普通文件库、批注与编辑版表不变。
