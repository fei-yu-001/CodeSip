# 鸿蒙安装版七七连接修复

用户确认连接失败发生在鸿蒙安装版。0.1.3 只有 ArkWeb 外壳，模型请求仍用网页 fetch。前一次修复了网页 CSP，但桌面浏览器收到网关 401 只能证明到达鉴权入口，不能代表 ArkWeb 能完成带有效密钥的流式对话。本次 HDC 未发现连接设备，没有把手机端的失败直接归因于 CORS、DNS 或证书。

0.1.4（10004）提供限定的原生网络通道：网页上的 Pi 继续负责对话和阅读工具，`qiqiTransport.ts` 保留已有 SSE/JSON 解析；`qiqiNative.ts` 把原生响应适配为 Response/ReadableStream。浏览器继续使用 fetch。鸿蒙 `QiqiBridge.ets` 使用系统 RemoteCommunicationKit 从本机直接请求模型地址，没有服务器模型代理，也没有新增诊断面板。

原生桥只注册 version/start/cancel。ArkWeb 白名单限制为 CodeSip HTTPS 域名，原生额外校验主页面和调用 frame 都为阅读器入口，导入文档不能调用。接口只接受 Chat Completions 的 POST，HTTPS 为默认要求，仅本机回环 HTTP 作为例外；禁止带账号、查询参数、锚点的地址。每次使用独立会话，只带模型授权和显式消息，不共享 Cookie，不配置响应缓存，禁止自动跳转，保留系统 TLS 校验。不记录密钥、正文、原始异常内容。

单次响应限制 4 MiB，连接超时 20 秒、空闲超时 60 秒、总时限 120 秒。停止、关闭对话、退出账号沿用现有 AbortSignal 取消链；离开页面和销毁 Web 组件会释放原生会话。原生失败不自动切回 fetch，避免重复发送或计费。API 20 起使用状态码事件逐段输出；API 12–19 在状态码确认前暂存有限响应，结束后展示，避免把鉴权错误当作成功回答。

错误文案区分鉴权、超时、DNS、TLS、跳转和普通网络错误，不展示服务可能回显的密钥。旧安装版在连接失败时提示更新鸿蒙安装包；网页端保持原有反馈。

## 安装与验收

本地产物：`.local/qiqi-harmony-20261128/CodeSip-0.1.4-signed.hap`。使用同一签名覆盖安装：`hdc install -r <HAP路径>`，不要卸载或清除应用数据。原生能力无法通过网页更新单独下发；网页的配套适配也需更新，可用头像菜单“检查应用更新 → 重载更新”。

在手机中确认应用版本 0.1.4，打开七七，用普通短问题验证能收到回答；停止后重新发送；再从合成阅读样例选段提问。确认既有设置、聊天记录和批注仍在。若仍失败，记录具体错误文案或数字错误码，不粘贴密钥或私人文档。本地验证产物位于忽略目录 `.local/qiqi-harmony-20261128/`。
