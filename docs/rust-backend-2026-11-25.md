2026-11-25 17:33:13（Asia/Shanghai）已部署 Rust 后端。生产 HTTP API 由原生程序处理，React/PWA、HarmonyOS ArkWeb 和 Obsidian TypeScript 插件保留现有接口。此前 Worker 解析、分批渲染及图片按需加载的优化保留；本轮没有修改前端产品代码。

## 架构与兼容范围

- Axum/Tokio 接收请求，2 个网络运行线程、最多 4 个后台工作任务和 4 个 SQLite 连接；SQLite、scrypt、ZIP 解压、JSON 序列化和 gzip 均在后台工作线程执行。ZIP/附件上传额外限制为同时 1 个，限制解压及上传缓冲占用。健康检查和静态文件不等待数据库工作许可。
- 保留 SQLite WAL、5 秒忙等待与所有既有表、字段及内容。库清单查询直接按账号和库 ID 读取；v1 增量读取用关联查询获取笔记内容。同步、批注、编辑副本的版本检查与写入在事务内完成，并发失效版本返回 409。
- 原有 scrypt 密码兼容：N=16384、r=8、p=1、64 字节结果，盐使用原有十六进制字符串的 UTF-8 字节。会话、插件令牌、设备密钥继续使用原有格式，不要求重建账号或登录状态。
- 覆盖初始化/登录/退出、库列表、ZIP 导入、示例、清单、文件、搜索、插件同步与令牌、阅读批注、编辑副本、v1 设备登录/增量同步/附件全部生产接口。
- 保留账号隔离、插件令牌范围、浏览器 Origin 检查、安全 Cookie、私有内容 no-store、导入文本隔离 CSP、路径与 ZIP 限额、批注墓碑、相同请求幂等重试。仍不执行导入源码，不改写原始笔记。
- 大文本与清单采用 `zlib-rs` 第 2 档 gzip，保留编码协商、1 KB 阈值和原文哈希。新增合成文档测试，防止迁移后的压缩体积明显增加。
- `server/` 旧版云 API 保留为兼容性测试基准；本地索引、局域网同步和 TypeScript 客户端组件继续由相关测试覆盖。发布包仅携带 Rust 服务程序，不携带旧版 Node 服务或 node_modules。

## 服务器性能实测

使用 `scripts/benchmark-backends.py`，在同一 Linux 主机的回环地址上顺序启动旧 Node 与新 Rust 进程，分别使用独立临时数据库和相同合成数据。每轮一个 641,620 字节文档、99 个短文件；预热后 60 次顺序文件读取、60 次清单读取、60 次并发度 6 的文件读取，包含 15 次预热，共 195 次读取，逐次校验原文 SHA-256。

此对比未套用生产服务的 50% 单核 CPU 配额，也没有测手机网络、渲染或滚动帧率。以下保留全部三轮结果，单位为毫秒，RSS 为 MiB。

| 轮次 | 后端 | 预热后 RSS | 文件中位 / P95 | 清单中位 / P95 | 并发文件中位 / P95 | 并发读取/秒 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | node | 117.15 | 13.395 / 32.275 | 1.671 / 2.404 | 76.914 / 95.903 | 60.91 |
| 1 | rust | 7.51 | 11.332 / 12.082 | 0.994 / 1.178 | 52.83 / 73.63 | 74.37 |
| 2 | node | 119.75 | 13.317 / 25.565 | 1.643 / 2.318 | 74.952 / 110.526 | 58.43 |
| 2 | rust | 8.83 | 11.272 / 11.727 | 0.95 / 1.035 | 50.983 / 71.422 | 75.34 |
| 3 | node | 118.96 | 13.03 / 30.996 | 1.593 / 1.907 | 75.172 / 92.067 | 62.27 |
| 3 | rust | 8.91 | 11.242 / 27.39 | 1.871 / 6.18 | 91.722 / 172.317 | 42.89 |

三轮 Rust 单次文件读取中位数为 11.242–11.332 ms，Node 为 13.030–13.395 ms；Rust RSS 为 7.51–8.91 MiB，Node 为 117.15–119.75 MiB。第三轮 Rust 清单和并发尾延迟较差，原因未定位，不能据此保证每次并发都更快。

同一合成文件的 gzip 体积：Node 237,273 字节，Rust 236,864 字节。首个候选使用第 1 档压缩时曾达到 367,600 字节，已在发布前发现并修正；期间也对比了 C zlib 的压缩档位，最终选择上述 Rust 压缩实现，第 2 档兼顾体积与耗时。原文内容和哈希始终一致。
